# 私域社群 AI 答疑与需求洞察工具

面向私域社群场景的 AI 答疑工具：把社群中高频重复的咨询交给模型自动回答，并把每一次提问沉淀为结构化数据，
生成主题分布与高频问题榜，反哺内容与选品决策。

区别于直接使用通用聊天工具，本工具解决的是**私有知识、回答可信度、数据回流**三件事——
回答可以挂企业内部知识，提问数据留在自己手里。

- **技术栈**：Python · Streamlit · SQLite · OpenAI 兼容接口（可切换多家服务商）
- **运行方式**：单文件启动，本地运行
- **当前状态**：答疑、打标、洞察看板三条链路已打通，支持在线 / 离线双模式

## 解决的问题

| 社群运营痛点 | 本工具的做法 |
|---|---|
| 高频问题重复回答，人工无法 7×24 响应 | 模型在线答疑，内置高频主题知识库兜底 |
| 通用大模型不了解品牌私有产品与活动 | 知识库可注入产品资料与科普内容，作为回答依据 |
| 回答可能涉及医疗效果等合规风险 | 回答带依据，超出范围时建议咨询专业医生 |
| 用户问了什么，运营侧看不到 | 提问自动落库并打标，生成主题分布与高频问题榜 |
| 有问题不等于有结论 | 基于统计数据生成内容 / 选品 / 社群三类运营建议 |

## 功能

- **AI 答疑**：接入大模型回答咨询，结尾附简要提示
- **AI 开关**：一键切换在线 / 离线，可用于对比演示同一问题的不同结果
- **内置知识库**：覆盖维生素 D、钙、DHA、益生菌、奶粉五个高频主题
- **快捷问题**：预置问题按钮，便于快速演示与回归验证
- **自动打标**：在线时由模型对提问归类（可处理知识库外的问题）；离线时回退关键词匹配
- **需求洞察看板**：主题分布、高频问题榜
- **运营建议生成**：将统计结果交给模型，产出内容 / 选品 / 社群三类建议；离线时使用规则模板兜底
- **数据持久化**：提问记录写入本地 SQLite，刷新与重启不丢失
- **配置持久化**：AI 开关、服务商、接口地址、模型、Key 保存到本地 `config.json`
- **数据管理**：支持清空对话与清空数据（带二次确认）

## 与通用聊天工具的区别

| 维度 | 直接使用通用聊天工具 | 本工具 |
|---|---|---|
| 私有知识 | 不知道品牌产品、价格与活动 | 可注入产品库与科普内容作为回答依据 |
| 合规与可信 | 可能给出医疗效果承诺 | 回答带依据，不确定时引导咨询专业渠道 |
| 数据回流 | 提问数据留在第三方，运营侧看不到 | 提问落库打标，形成需求洞察 |
| 用户关系 | 用户在与第三方工具对话 | 品牌自有触点，关系沉淀在品牌侧 |

## AI 在工具中的三类作用

1. **答疑**：生成回答内容
2. **归类**：为每条提问打主题标签（覆盖知识库之外的问题）
3. **辅助决策**：读取统计数据，生成运营建议

在线与离线两种模式对应两条链路，离线模式用于验证"没有模型也能跑通"的兜底能力：

```
在线：提问 → 模型回答 → 模型打标 → 落库 → 统计 → 模型生成建议
离线：提问 → 知识库匹配 → 关键词打标 → 落库 → 统计 → 规则模板建议
```

## 快速开始

### 方式一：双击启动

Windows 下双击项目目录中的 `启动助手.bat`，自动启动并打开浏览器。

### 方式二：命令行

```bash
pip install streamlit openai
python -m streamlit run app.py
```

访问 http://localhost:8501

### 使用

1. 左侧「启用 AI 模式」切换在线 / 离线
2. 选择服务商，界面自动填充默认接口地址与模型，也可手动修改
3. 在线模式填入 API Key（本地 Ollama 可不填）；离线模式走内置知识库
4. 点击快捷问题或自由输入提问
5. 切换到「用户洞察」页查看主题分布、高频问题与运营建议

### 支持的服务商

| 服务商 | 接口地址 | 默认模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 豆包（火山方舟） | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-1-5-pro-32k-250115` |
| Kimi（月之暗面） | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 通义千问（阿里云） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Ollama（本地） | `http://localhost:11434/v1` | `qwen2.5` |

模型名以各服务商最新文档为准，可在界面手动修改；任何兼容 OpenAI 接口的服务均可接入。

## 设计取舍

| 决策点 | 采用方案 | 放弃的方案 | 原因 |
|---|---|---|---|
| 知识注入方式 | 内置知识库 + 提示词注入 | 完整 RAG 向量检索 | 当前知识量小（5 个主题），向量检索的复杂度与收益不成比例；结构上已预留替换位置 |
| 离线能力 | 关键词匹配 + 规则模板 | 仅支持在线模式 | 演示与外网受限场景下仍需可用，同时可作为在线效果的对照 |
| 厂商接入 | 统一 OpenAI 兼容协议，可切换 6 家 | 绑定单一厂商 | 成本、时延、可用性差异较大，切换成本应接近于零 |
| 数据存储 | 本地 SQLite | 云端数据库 | 单机单用户场景，减少部署依赖；数据不外流 |
| 交互形态 | Streamlit 单文件 | 前后端分离 | 工具定位为验证与自用，优先缩短迭代路径 |

## 已知限制

- 单文件 Streamlit 应用，无鉴权与多用户隔离，仅适合本地或内网使用
- 知识库为关键词匹配 + 提示词注入，未实现向量检索；知识量增大后召回效果会下降
- 主题归类依赖模型或关键词，未做严格聚类，"其他"类别占比可能偏高
- `config.json` 中 API Key 为明文存储（仅本地）
- 未接入真实业务流量，洞察数据来自模拟提问

## 目录结构

```

├── app.py              # 主程序（单文件：界面 + 答疑 + 打标 + 洞察）
├── config.json         # 本地配置（首次运行自动生成，含 API Key，请勿提交）

├── 启动助手.bat        # 一键启动脚本
└── README.md
```

## 扩展知识库

编辑 `app.py` 中的 `QA_KB` 列表，按以下格式追加条目：

```python
{"q": "关键词", "a": "回答内容"},
```

关键词用于离线匹配，回答内容同时作为在线模式下模型的参考依据。
